# Подключение Supabase к SCIENCE QUEST KZ

Эта инструкция рассчитана на первый опыт работы с Supabase. Исходный код приложения после подключения менять не потребуется.

## Шаг 1. Создайте проект

1. Откройте [supabase.com](https://supabase.com/) и войдите в аккаунт.
2. Нажмите **New project**.
3. Выберите организацию, название проекта и регион.
4. Дождитесь, пока проект перейдёт в состояние готовности.

## Шаг 2. Включите Anonymous Sign-Ins

1. В левом меню Supabase откройте **Authentication**.
2. Откройте **Sign In / Providers**.
3. Найдите настройку **Allow anonymous sign-ins**.
4. Включите её и сохраните настройку.

Ученику не потребуется email или телефон. Supabase создаст постоянный anonymous UUID, который сохранится в браузере и будет внутренним идентификатором профиля.

## Шаг 3. Откройте SQL Editor

В левом меню выберите **SQL Editor**, затем нажмите **New query**.

## Шаг 4. Примените migration

1. Откройте файл `supabase/migrations/202608220001_leaderboard.sql` из этого проекта.
2. Скопируйте его содержимое целиком в SQL Editor.
3. Нажмите **Run**.
4. Убедитесь, что запрос завершился без ошибки.

Migration не удаляет таблицы и не очищает данные. Она создаёт таблицы, индексы, RLS-политики и защищённые RPC. Повторный запуск предназначен только для той же версии схемы; перед изменением уже работающей базы используйте новую migration.

## Шаг 5. Скопируйте Project URL

1. Откройте диалог **Connect** вверху страницы проекта. Альтернативный путь: **Integrations → Data API**.
2. Найдите значение **Project URL** (Data API URL).
3. Скопируйте адрес вида `https://abcdefgh.supabase.co`.

## Шаг 6. Скопируйте публичный ключ

Откройте **Settings → API Keys** и скопируйте **Publishable key** вида `sb_publishable_...`. Если проект показывает только legacy-ключи, допустим **anon** key; не выбирайте secret key.

Приложение использует современную переменную `VITE_SUPABASE_PUBLISHABLE_KEY` для публичного publishable key проекта.

Никогда не копируйте в frontend секретный или `service_role` key.

## Шаг 7. Создайте `.env.local`

В корне проекта, рядом с `package.json`, создайте файл `.env.local`:

```env
VITE_SUPABASE_URL=https://abcdefgh.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_ваш_публичный_ключ
```

Не добавляйте кавычки и пробелы вокруг `=`. Файл `.env.local` уже исключён из Git. В репозитории остаётся только безопасный `.env.example` без настоящих значений.

## Шаг 8. Запустите приложение

После создания `.env.local` полностью перезапустите dev server:

```text
npm run dev
```

В development-консоли должны появиться сообщения:

```text
[Supabase] Connected
[Auth] Anonymous sign-in available
[Leaderboard] RPC available
```

В разделе **Профиль** development-сборки также появится блок **Backend Status**. Он не показывается ученикам в production.

## Шаг 9. Создайте первого ученика

1. Откройте сайт.
2. Выберите уникальный nickname, science avatar и класс.
3. Школу можно оставить пустой.
4. Сохраните профиль.
5. Пройдите первый уровень и откройте рейтинг.

После обновления страницы должен сохраниться тот же anonymous аккаунт, nickname и прогресс. Не очищайте данные сайта в браузере, иначе локальная anonymous-сессия будет удалена.

## Шаг 10. Проверьте два устройства

1. Откройте игру на первом устройстве или в одном браузерном профиле и создайте первого ученика.
2. Откройте игру на втором устройстве либо в другом браузерном профиле и создайте второго ученика.
3. Пройдите по уровню каждым учеником.
4. Откройте **Рейтинг** на обоих устройствах и убедитесь, что видны оба nickname.

## Автоматическая проверка пяти учеников

Используйте только отдельный тестовый Supabase project с применённой migration:

```powershell
$env:SUPABASE_TEST_URL='https://abcdefgh.supabase.co'
$env:SUPABASE_TEST_PUBLISHABLE_KEY='sb_publishable_ваш_публичный_ключ'
npm run test:leaderboard:integration
```

Тест создаёт Student A–E через Anonymous Auth, проверяет сортировку, Top 3, personal rank, weekly/monthly, unique nickname, idempotency, anti-farm и RLS. После проверки каждый тестовый пользователь удаляет собственный аккаунт через разрешённый RPC. Admin-ключ тесту не нужен.

## Временная зона рейтинга

Недельный и месячный периоды рассчитывает база данных по серверному времени в зоне `Asia/Almaty`:

- неделя: понедельник 00:00 — следующее воскресенье 23:59:59;
- месяц: первый день месяца 00:00 — начало следующего месяца.

Дата и временная зона телефона ученика на рейтинг не влияют.

## Безопасность

- браузер отправляет только level ID, accuracy, mistakes и уникальный submission ID;
- XP, Science Points, Challenge Points и stars рассчитывает RPC;
- основной XP одного уровня выдаётся один раз;
- повтор одного submission ID идемпотентен;
- RLS запрещает прямое изменение результатов и чтение чужих приватных профилей;
- публичный leaderboard не возвращает UUID, email, токены, provider data или название школы.
